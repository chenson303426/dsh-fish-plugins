# dsh-feeling · 鱼的感情

不只是“今天开不开心”，而是**她对每一个对象的态度**：亲近、信任、分享深度、求助倾向，以及那些“还没解决的事”。

## 做什么

- 每回合最多一次评估，从**用户说的话**里抽 0~2 个关系事件（夸奖、失约、越界、道歉……），证据、解读、不确定度都落库
- 同样的行为有冷却，防止“换句话夸十次”把分数刷满
- **未解决事项**单独存：可以一直生气，愤怒有 floor，被哄/道歉只对**相关**事项生效
- **约定**单独存：`deadlineAt / detectedAt / fulfilledAt` 三个时间，“发现晚”不等于“迟到”
- 每轮注入两行以内：`【关系·阿元】` + `【当前事项】`，**不给数字**

## 关键配置

| 键 | 说明 |
|---|---|
| `caps` | 单事件对关系的最大改变 |
| `rolling24h` | 每 24 小时的关系变动上限 |
| `decay.angerHours` | 不满的半衰期 |
| `expectationGraceMinutes` | 约定宽限（默认 15 分钟） |
| `targetId` / `ownerQq` | 对谁记账、对方的 QQ |

## 和别的插件怎么交互

- 写 `~/.dsh/mood/inbox.jsonl`：关系事件 → 心情
- 写 `~/.dsh/feeling/latest-event.json`：给 mood 当“刚才发生了什么”
- **内建 availability**：她的睡眠、午睡、随机小睡，以及你的不在窗口；`~/.dsh/availability-config.json` 是它的规则文件
- 读 `~/.dsh/sulk/observations.jsonl`：沉默观察按 episode 去重，只有带约定 ID 的才生成事项

## 已知限制

- 事件抽取靠模型判断方向（谁对谁），反讽或玩笑可能误判；日志里能看证据与解读
- 关系分只由“用户做的事”改变；她自己的行为不改关系分
- availability 目前住在 feeling 里，将来会拆成独立插件
