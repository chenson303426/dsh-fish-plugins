# dsh-sulk · 鱼的脾气

被晾着了会主动开口的插件。她不按固定间隔发消息，而是**先判断这段对话是怎么结束的**，再决定等多久、说什么。

## 做什么

- 每次沉默只判一次场景，三选一（互斥）：`ignored` 被晾着 / `wrapped` 正常收尾 / `idle` 自然停住
- 到时间后**掷骰子**决定这次要不要开口，命中率按场景不同（默认 25% / 10% / 20%）
- 命中后进入冷却；同一段沉默有次数上限；每天总量封顶
- **跨天重置**：哪怕几天没人理，第二天仍有机会开口
- 每次开口前写一条 `proactive_opportunity` 事件，让 mood 有机会更新心情

## 关键配置

| 键 | 说明 |
|---|---|
| `enabled` | 总开关（关掉后连日志都不写） |
| `dryRun` | 只记账、不真发 |
| `scenes.*.minutes` | 沉默多久开始掷 |
| `scenes.*.intervalMinutes` | 隔多久掷一次 |
| `scenes.*.probability` | 命中率 |
| `dailyCap` | 每 24 小时最多成功开口几次 |
| `quiet` | 不主动发送的时段（默认 01:00–09:00） |

## 和别的插件怎么交互

- 读 `~/.dsh/feeling/availability-state.json`：她睡着或用户不在窗口时**不搭话**
- 写 `~/.dsh/mood/inbox.jsonl`：沉默阶段 → 心情；开口机会 → 只生成内心旁白
- 往会话里用 `followup` 塞动机文案，来源标记为 `sulk`，其他插件据此区分“她自己说的”和“用户说的”

## 已知限制

- 沉默计时在内存里，重启会重新开始（跨天额度也会按重启时间重算）
- 文案来自 `scenes.*.prompt`，是**动机**不是台词；具体怎么说由模型决定
- 掷骰结果不落盘，重启后重排
